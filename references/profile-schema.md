# 画像格式

画像只记**会改变书里某条建议是否适用**的事实。兴趣爱好、性格、审美不进来，除非能对上书的某一节。

## 领域 → 对应的书节

| 领域 | 要的事实 | 主要对应 |
|---|---|---|
| 身体 | 年龄性别、体重/BMI、血压血糖尿酸、已确诊的病、在用的药与补剂、烟酒、运动量、睡眠 | 1, 2, 6, 16, 24, 28, 34 |
| 作息与精力 | 几点睡、每周工时、深夜活动比例、被打断的情况 | 2.13, 3, 4 |
| 家庭 | 婚育、孩子年龄、父母年龄与健康、谁靠你的收入生活 | 5.40, 10, 17, 18, 20, 30 |
| 钱 | 收入来源与个税档位、社保公积金、保险、负债、投资方式、订阅 | 5, 6, 7 |
| 工作与生意 | 雇佣还是自己开公司、主营业务形态、收款方式、是否面向公众提供服务、服务器在哪 | 8, 9, 11, 12, 19, 26 |
| 居住出行 | 租还是买、所在城市、出境频率、证件到期日 | 15, 21 |
| 正在发生的事 | 未结的纠纷、就医、证件、税务期限 | 8, 13, 14, 25, 29 |

## 每条事实的写法

```
- 体重 82kg、BMI 27.5（2026-03-02）　[fs] ~/.claude/projects/<桶>/memory/health.md:12
- 每周有消息的时段折合约 60 小时（亲手发消息的 15 分钟格）　[fs] activity.py <日期> 输出
- 父母健在、本人独生子女　[infer·待验] 个税赡养老人一项按独生子女的全额扣，现行标准只有独生子女能扣满
```

取证级别：

| 级别 | 含义 |
|---|---|
| `fs` | 记忆原文或脚本输出里直接写着 |
| `user` | 记忆里注明是用户本人说的 |
| `log` | 抄自日志或旧记录，没再复核（写清是哪天的） |
| `infer` | 推出来的，**必须同时标待验**，并写出推理依据 |

🔴 档案里写着「预测 / 预计 / 估算」的数（比如「2026 年预测：全年个税 0」）一律记 `log`，并写明它是哪天、按什么假设算的。
不能因为原文白纸黑字就记成 `fs`：首跑时就这样把一个只算了工资的预测写成了「全年个税 0」，用户当场指出不对。

## 画像末尾两节

- **缺口**：档案里查不到、但会改变某条建议的事实，每条写清「影响第几节第几条」。最多列 8 条，按影响大小排。
- **时效**：画像里最旧的关键事实是哪天的（体重、体检这类过半年就要标「可能过时」）。
